# 近畿の公開データ収集（kinki-opendata）

提供元が過去分を残さない公開データを、毎日自動で集めて残すリポジトリです。いまは **近畿の交通量（5分値）** を集めています。
※このリポジトリはClaudeを使用しています

## 近畿の交通量（5分値）

国土交通省の交通量API（データ提供：日本道路交通情報センター）は、5分値を約1か月しか残しません。全国の1時間値と関東の5分値は [yasumorishima/japan-road-traffic](https://github.com/yasumorishima/japan-road-traffic) が毎日保存していますが、近畿の5分値を保存している場所は見つからなかったため、ここで集めています。

- **範囲**：経度 134.2〜136.5、緯度 33.4〜35.9（近畿のおおよその範囲。境目では中部・中国の観測点が少し混ざる）
- **種類**：常設のトラフィックカウンター（`loop`）と、CCTV映像のAIカウンター（`cctv`）。道路種別は一般国道（`road3`）と高速自動車国道（`road1`）
- **置き場所**：リリース `raw-YYYYMM`（日本時間の月）に、日ごとのファイル `kinki_{loop|cctv}_5m_road{3|1}_YYYYMMDD.csv.gz`
- **列**：提供元の列名（日本語）のまま。最後の2列に `経度`・`緯度` を足している。`時間コード` は日本時間の `YYYYMMDDhhmm`（区間の始まり）
- **台帳**：[`data/manifest_traffic.csv`](data/manifest_traffic.csv) に、日ごと・種類ごとの行数、そろった時刻の数、欠けた時刻、状態を記録

### 欠けの扱い

1日は288時刻（5分×24時間）。観測点の数がその日の中央値の半分に満たない時刻も「欠け」として数えます。

| 状態 | 意味 |
| --- | --- |
| `complete` | 288時刻すべてそろった |
| `complete_with_gaps` | 2日以上前の日で、欠けが5%以内。提供元にも値がないとみなしてそのまま保存 |
| `partial_before_expiry` | 欠けが多いまま、提供元から消える直前（28日以上前）になったので保存 |
| `empty_before_expiry` | 消える直前まで1行も取れなかった（ファイルなし） |

欠けが多い日は、提供元に残っている間、次の実行で取り直します。

### 集め方

[`.github/workflows/collect-traffic.yml`](.github/workflows/collect-traffic.yml) が1日3回動き、[`scripts/collect_traffic.py`](scripts/collect_traffic.py) が「提供元にまだ残っていて、ここにまだない日」を、消えそうな日から順に1時間ずつ取ります（リクエストの間は1秒あける）。ファイルをリリースに置けたあとで台帳に記録するので、途中で失敗した日は次の実行でやり直されます。動作は偽のAPIで試験しています（[`tests/`](tests/)）。

## 近畿の気象警報・注意報

### 電文（防災情報XML）— こちらが主

気象庁防災情報XMLの「随時・長期フィード」（[extra_l.xml](https://www.data.jma.go.jp/developer/xml/feed/extra_l.xml)、毎時更新・7日分ほどの全入電を掲載）を毎時見て、**全国**の気象警報・注意報の電文（種類コードが `VPWW` で始まるもの）を **1件ずつ、加工せずに** 保存しています（2026-11-04 の初回だけ近畿6府県。同じ日の2回目から全国）。

- **海上警報**も保存している（2026-11-04 午後から）：「その他」の長期フィード（[other_l.xml](https://www.data.jma.go.jp/developer/xml/feed/other_l.xml)）から、地方海上警報（`VPCU51`：海上台風・暴風・強風・風・うねり警報など）と全般海上警報（`VPZU…`）。地方海上予報（`VPCY51`）は今は取っていない。海上警報は管区気象台などが発表するので、フォルダは発表官署の地域コード（例：`040000`）
- 同じ発表が、旧形式（`VPWW53`・`VPWW54`）と令和6年からの分野別の形式（`VPWW55` 以降）の両方で出る。数えるときは1つの形式にそろえる
- 電文のファイル名の日時は **UTC**（例：`20261103192808` は日本時間 11/4 04:28）。月のフォルダもファイル名の月（UTC）
- 1回の実行で取る電文は1,500件まで。残りは次の回に回す（`fetch_log` の `deferred`）。フィードに7日分残るので取りこぼさない

- **置き場所**：[`data/warning_xml/{府県コード}/{YYYY-MM}/{電文のファイル名}.gz`](data/warning_xml/)（gzip で圧縮した電文そのもの）
- **実行の記録**：`data/warning_xml/fetch_log_YYYY-MM.csv`。実行ごと・フィードごと（`feed` 列：`extra` が気象警報、`other` が海上警報。空欄は 11/4 の最初の数回で `extra`）に、フィードの件数・期間、近畿の警報の件数、新しく保存した件数、失敗した件数。フィードの最も古い入電が前回の実行より新しかったとき（間を取りこぼした可能性があるとき）は `gap_suspected` が 1 になる
- **なぜ長期フィードか**：GitHub の定期実行は混んでいると1〜2時間遅れることがあり、11/3〜11/4 のホームページのJSON（下）の記録では発表から取得までに最大2時間以上かかっていた。長期フィードなら、遅れても数日以内に動けば全部拾える

### ホームページのJSON（11/3〜、比べるために並行して残している）

気象庁のホームページの警報・注意報のJSONは「今の最新の発表」だけを返し、過去の発表は機械で読める形では残りません。そこで、近畿6府県（大阪 `270000`・京都 `260000`・兵庫 `280000`・奈良 `290000`・和歌山 `300000`・滋賀 `250000`）を10分ごとに見て、**中身が変わったときだけ** 保存しています。

- **置き場所**：[`data/warning/{府県コード}/{YYYY-MM}.jsonl`](data/warning/)。1行が1回分で、`fetched_at_jst`（取った時刻）、`latest_report_datetime`（その中で最も新しい発表時刻）、`sha256`（中身の指紋）、`body`（気象庁のJSONそのまま、加工なし）
- **読み方**：`body` は発表の種類（`dataTypeCode`）ごとに最新の1件が並ぶ。警報・注意報のコードの意味は気象庁の資料、または [shiromatz/Japan-Meteorological-Agency-Weather-Forecast](https://github.com/shiromatz/Japan-Meteorological-Agency-Weather-Forecast) の `warningCode/r8/` を参照
- **限界**：10分の間に同じ種類の発表が2回あると、前のほうは取れない。GitHub の定期実行が遅れたり飛んだりした間も同じ。取った時刻は `fetched_at_jst` で、実行の記録は Actions タブで確かめられる
- **過去の記録であり、今の警報ではありません。** 今の情報は気象庁のホームページで確かめてください。

[`.github/workflows/collect-warning.yml`](.github/workflows/collect-warning.yml) と [`scripts/collect_warning.py`](scripts/collect_warning.py) で集めています。

## 出典と利用条件

出典：「交通量 API（国土交通省）機能による交通量(参考値)」を加工して作成
（データ提供：公益財団法人日本道路交通情報センター <https://www.jartic-open-traffic.org/> ）

- 値は参考値で、国土交通省の公式な交通量調査の結果ではありません。故障中の観測点は 0 と異常フラグで返ることがあるので、フラグの立った行は除いて使ってください。
- このリポジトリは国土交通省・日本道路交通情報センターが作成または保証したものではありません。
- データの利用条件は提供元の利用規約に従います（CC BY 4.0 と互換と示されています）。

気象警報・注意報：出典：気象庁ホームページ（https://www.jma.go.jp/bosai/warning/）。気象庁ホームページのコンテンツ利用規約（公共データ利用規約に準拠）に従って保存しています。このリポジトリは気象庁が作成または保証したものではありません。
